# EmpathicVisionEpoch 技术栈与路线图

这份文档整理了项目的核心技术栈与开发路线图，作为后续实现与协作的统一参考。

## Part 1 核心技术栈 (The Arsenal)

### 前端与采集端 (Client)

- 框架: Flutter (Dart)
  - 理由: 单套代码覆盖 iOS/Android，渲染性能强，实时取景器更稳。
- 端侧轻量计算: TFLite (TensorFlow Lite) 或 NCNN
  - 理由: 在手机侧完成运动/模糊检测，过滤垃圾图像，节省带宽与云算力。

### 后端与算法服务 (The Brain)

- Web 框架: FastAPI
  - 理由: 轻量、异步友好，适合图片上传与 I/O 密集场景，自动生成 API 文档。
- 计算机视觉 (CV)
  - 基础处理: OpenCV (透视变换、边缘提取)
  - OCR: PaddleOCR
    - 理由: 中文识别效果更稳，适合消防图中的小字与倾斜文字。
  - 特征提取: SuperPoint + SuperGlue (PyTorch)
    - 理由: 学术级特征点鲁棒性更强，是论文亮点。
- 图计算
  - NetworkX: 原型验证
  - Neo4j: 生产环境图数据库

### 基础设施 (Infra)

- 数据库: PostgreSQL (用户数据与图片元数据)
- 存储: MinIO (对象存储，兼容 S3)
- 部署: Docker Compose (一键拉起全栈服务)

## Part 2 开发方案路线图 (The Roadmap)

### Sprint 1 骨架构建 (The Skeleton)

- 目标: 输入消防图，输出拓扑图数据结构。
- 任务清单:
  - 图像预处理: OpenCV 识别四角并做透视变换 (Perspective Transform)。
  - 语义提取: PaddleOCR 识别“楼梯/房间号”等文本并记录像素坐标。
  - 骨架化: 传统 Skeletonization 将走廊抽成单像素骨架线。
  - 建图: 交叉点作为节点，线段作为边，生成 NetworkX 图对象。
- 交付物: 可序列化的节点/边数据 (JSON) + 可视化验证图。

### Sprint 2 视觉指纹 (The Eyes)

- 目标: 建立“图片 <-> 地点”的映射。
- 任务清单:
  - 采集: 录制走廊视频，抽取关键帧。
  - 清洗: 过滤模糊、过曝、纯色等废片。
  - 向量化: SuperPoint 输出 256/512 维特征向量。
  - 入库: 向量库 (Faiss/Milvus/NumPy 原型)。
- 交付物: 特征库 + 关键帧索引。

### Sprint 3 融合与定位 (The Fusion)

- 目标: 将视觉流定位到骨架图上。
- 任务清单:
  - OCR 锚定: 检测到“402” -> 关联消防图节点 -> 校准位置。
  - 序列对齐: 光流估计用户移动距离，结合拓扑图预判路径。
  - 闭环检测: 识别特定视觉锚点 (如灭火器箱) 做误差修正。
- 交付物: 视觉定位 + 图上位置估计。

### Sprint 4 导航交互 (The Experience)

- 目标: 让用户“能看懂、敢跟走”。
- 任务清单:
  - Flutter 极简 UI: “我在哪 / 要去哪”。
  - 视觉引导: 显示下一张关键帧 + 简短文字提示。
- 交付物: 可用的交互式导航原型。

## 独家技术建议 (Pro Tips)

- Wi-Fi/蓝牙指纹:
  - 作为视觉定位的辅助过滤器，快速判断楼层或区域。
- 冷启动策略:
  - “赏金猎人模式”: 上传消防图/采集走廊视频可换奖励。
- 开发顺序:
  - 先在 Jupyter/脚本端跑通“消防图 -> 拓扑图”和“视频 -> 特征匹配”，
    再做 App，避免前端先行浪费时间。
